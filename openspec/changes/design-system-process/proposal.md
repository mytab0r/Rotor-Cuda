# Design-system process both a designer and a developer can maintain

## Summary

Make the design system a repository artifact with one source of truth, a
generated token layer, machine-checkable component contracts, a live gallery
that is itself audited, and a sign-off process where the author is never the
approver. Prepared by taking the designer's and the engineer's positions
independently and resolving their disagreements explicitly.

Status: proposed. Inputs: two role reviews, 2026-11-21.

## Positions and resolutions

| Question | Designer said | Engineer said | Resolution |
|---|---|---|---|
| Source of truth | DTCG JSON in git, Figma is an editor | git JSON with review, Figma is an editor | Same: `design/tokens/tokens.json`; Figma export arrives as a PR input |
| Token pipeline | `build-tokens.mjs`, generated region committed | zero-dep generator, marked region inside `site.css`, `tokens.ts` | Same; no Style Dictionary until npm exists in `web/` |
| Component docs | one page per component, fixed template | manifest + generated static gallery | Both: manifest is machine contract, page is human contract, gallery is rendered from production markup |
| Workshop | gallery in repo | gallery, not Storybook | Static gallery `/design`; Storybook rejected as a second toolchain |
| Visual review | visual diff + focus/reduced-motion/stress captures | pixelmatch inside the existing CDP audit | Same: one screenshot source, pixelmatch on top, baselines regenerated by `workflow_dispatch` |
| Figma sync | export as PR, no reverse sync | mapping file fails on renames | Same: forward-only sync with `figma-map.json` |
| Ownership | designer owns semantic names and values | primitive names by designer, semantic by engineer | Designer owns semantic values and role names; engineer owns primitive scale mechanics, mapping, generators, detectors |
| Token rename | not discussed | freeze current 95 names | Freeze; renames are a separate atomic change |

## Decisions

1. **Tokens.** `design/tokens/tokens.json` (W3C DTCG) is the only source. The
   current 95 custom properties (`apps/site/site.css:683-795`) are frozen as a
   contract; legacy aliases (`--bg`, `--panel`, `--accent`) stay as semantic
   aliases. `scripts/build-tokens.mjs` rewrites the `/* tokens:start */ ...
   /* tokens:end */` region of `site.css` and generates
   `design/generated/tokens.ts`; `--check` fails when the committed output is
   stale. Light theme is a second generated block for semantic colours only.
2. **Token gates.** New detectors, each with a `docs/process/defects.json`
   entry: `token-contract` (JSON token without CSS declaration and vice versa,
   `var()` without a token), `orphan-token` (no consumer; 30-day grace or an
   explicit `"reserved": true`), `theme-parity` (colour role without a light
   value), `radius-scale`, `raw-hex-outside-root` (the 63 raw hex lines outside
   `:root` and the light block), `legacy-selector`.
3. **Component contract.** `design/components/<name>.json` is the machine
   contract: `name`, `version`, `status`, `element`, closed `variants` and
   `sizes` lists, `states`, `requiredAttrs`, `forbidden`, `slots`, `tokens`,
   `detectors`, `docs`. `scripts/check-components.mjs` fails on an unknown
   variant or size, a missing required attribute, a page-local `<style>` for a
   shared family, or a state missing from the gallery. Semver per family;
   removing a variant or a required attribute is breaking.
4. **Human documentation.** `docs/design-system/components/<name>.md` follows a
   fixed template: purpose and when not to use it, anatomy and slots, API,
   state matrix with screenshots, motion and reduced-motion, accessibility
   (role, name, described-by, keyboard, live region, contrast), copy rules,
   do/don't on real renders, detector IDs or an explicit
   "not machine-checkable" note, owner and changelog.
5. **Live gallery.** `apps/site/design.html` is generated by
   `scripts/build-gallery.mjs` from manifests and production markup, added to
   `static_asset`, to the audit route list and to `route-coverage`; it is
   audited at 375/768/1280 in both themes. A broken example is a red CI.
6. **Review and sign-off.** A visual change requires sign-off by someone other
   than its author. The sign-off carries: before/after screenshots of the
   changed blocks at 375/768/1280 in both themes, a focus-visible capture and
   tab order, a reduced-motion capture, stress fixtures (long label, single
   letter, non-Latin, empty, error, zero, very large number), the visual-diff
   report link and a green `ui-audit`. "Looks fine at 1280 dark" is not a
   sign-off. `CODEOWNERS` covers `design/**` and `docs/design-system/**`.
7. **Automation.** Fast CI job on every PR: token `--check`, component check,
   defect ledger, `node --check`. Render job only for changed site paths. Axe
   (`serious`/`critical` fail) injected into the same CDP context; size budgets
   per route; baselines regenerated only on ubuntu.
8. **Handoff.** Weekly 30-minute review of the gallery, open design debt and the
   `docs/design-system/decisions.md` log. Token changes do not ride inside
   feature PRs. Designer writes values and role names; engineer wires mapping,
   generation and consumers.

## Order before the framework switch

0. Freeze the token-name contract (`design/tokens/tokens.contract.json`).
1. Extract the JSON from `site.css` and the light block; generator writes the
   region; prove computed-style equivalence before/after.
2. Add `token-contract`, `radius-scale`, `raw-hex-outside-root`,
   `legacy-selector` with ledger entries.
3. Manifests for the normalized families (button, icon-button, field,
   segmented, chip, status, card, stat, table, nav/breadcrumb/pager,
   empty/error/skeleton) plus the gallery and `check-components`.
4. Pixelmatch baselines, axe, budgets, CI split.
5. Generate `apps/site/routes.json` and switch `ui-audit.mjs` from parsing
   `src/coordinator/mod.rs` to the manifest, so `route-coverage` survives the
   Astro move.

Only after 0-5 does the Astro migration consume this system unchanged.

## Out of scope

- Renaming existing tokens or restyling pages.
- Buying a SaaS (Chromatic, Figma seats are optional inputs, not gates).
- Replacing the CDP audit with Playwright.
