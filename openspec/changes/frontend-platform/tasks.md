# Tasks — frontend platform

Phases from `proposal.md`. Each phase lands as its own PR; the split must never
ship two renderers for the same route.

## 0. Skeleton

- [ ] `web/` Astro app: pinned deps, committed lockfile, `npm ci` in CI, area in
      `projects.json`.
- [ ] `data/chains.json` and `data/puzzles.json` consumed by both Rust and Astro
      (one source, generated or imported).
- [ ] CSP plan and provider allowlist documented before any page moves.

## 1. Pilot

- [ ] `/mnemonic-converter` on Astro (islands only where needed).
- [ ] Acceptance: route JS <= 45 KB gzip, `ui-audit` 0 violations, LCP <= 1.5 s,
      bit-identical vectors, screenshots from a second agent.

## 2. Presentation and hubs

- [ ] Prerequisite: `data/routes.json` is the routing map (pattern, template,
      renderer, data sources, auth, status) and `scripts/check-ssot.mjs` fails
      when the coordinator serves a route missing from it or names a missing
      template. The operator view is `/cabinet/admin/site-map`. No phase-2 page
      moves before the map covers every coordinator route family.
- [ ] Landing, docs, faq, disclaimer, donate, tools, converters, tx, vanity,
      milk-sad (~27 pages) prerendered.
- [ ] Search, theme toggle and shared nav behave as today.
- [ ] Sitemap/robots generated by Astro; counts match 18 chains.

## 3. Key and directory

- [ ] `/private-keys` and chain pages (page 1 prerendered, later pages on edge).

## 4. Seed and puzzle

## 5. App shell

## 6. Cutover
