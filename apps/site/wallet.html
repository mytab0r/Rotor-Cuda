Wallet Cabinet

Cabinet wallet

Keep WIF and hex keys in an encrypted vault on this device and watch the addresses they control. The vault is encrypted with a passphrase you choose; the server never receives the passphrase, a private key or a WIF.

Local vaultPBKDF2 + AES-GCMWatch-onlyNo signing yet

The vault lives in this browser's IndexedDB. Losing the passphrase loses the keys: there is no recovery and the server cannot help. Export an encrypted backup and keep it somewhere safe. Testnet sending is not part of this phase; nothing on this page signs or broadcasts a transaction.

Create a vault

Use at least 8 characters. The passphrase derives the AES key with PBKDF2-SHA256 (600,000 iterations); it is kept only in memory while the vault is unlocked.

Unlock the vault

A wrong passphrase cannot decrypt anything. The vault locks itself after 10 minutes without activity and whenever this page is hidden.

Import a key

A WIF is checked and mapped to Bitcoin, Litecoin or Dogecoin by its version byte: compressed Bitcoin WIFs use native SegWit, uncompressed ones use legacy P2PKH, Litecoin uses native SegWit and Dogecoin uses legacy. Testnet WIF versions (0xEF, 0xF1) are recognized but not stored in this phase because the local core returns mainnet addresses only. Any 64-character hex key needs an explicit chain. The address is derived with the local WASM core first; a key whose address cannot be derived is not stored.

What is stored

IndexedDB database rotor-wallet, store vault: one versioned record with a random 16-byte salt, PBKDF2-SHA256 with 600,000 iterations, AES-GCM-256 and a fresh 12-byte IV on every save. The record holds only ciphertext; the passphrase and the keys are never written to localStorage, the URL, logs or the network.

This page does not sign or broadcast transactions. Watch-only means it can show addresses, links and (opt-in) balances.
