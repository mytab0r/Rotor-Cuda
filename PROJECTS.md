# Projects and contracts

`projects.json` is the machine-readable source of truth. Every tracked path is
owned by exactly one area; the most-specific glob wins.

| Area | Owner | Owns | Build | Test |
|---|---|---|---|---|
| `site` | site-ui | `apps/site/**`, `data/**` | `node --check apps/site/*.js` | `node apps/site/worker-test.mjs apps/site/rotor_wasm.wasm` |
| `web` | site-ui | `web/**` (Astro pilot) | `npm --prefix web ci && npm --prefix web run build` | `npm --prefix web test` |
| `coordinator` | coordinator | `src/coordinator/**`, `src/bin/rotor-coord.rs`, `tests/coordinator_*` | `cargo build --release --bin rotor-coord` | `cargo test --test coordinator_api --test coordinator_client` |
| `wasm-core` | wasm-core | `crates/rotor-wasm/**` | `sh scripts/build-wasm.sh` | `cargo test -p rotor-wasm`; `smoke.mjs`; `worker-test.mjs` |
| `desktop` | desktop-tools | remaining `src/**` and `tests/**`, `Rotor-Cuda/**`, legacy trees, `build.rs`, `Cargo.toml` | `cargo build --release [--features gpu]` | `cargo test --release [--features gpu]` |
| `ops` | ops/docs | `.github/**`, `.claude/skills/**`, `deploy/**`, `scripts/**`, `openspec/**`, `docs/**`, `Dockerfile`, root docs | `node scripts/check-projects.mjs` | `node docs/site-map/site-map-test.mjs`; `node scripts/check-projects.mjs` |

## Cross-area contracts

- **Site -> coordinator (compile time).** `src/coordinator/mod.rs:31-41`
  embeds `apps/site/*.html`, `site.css`, `site.js`, `theme.js`, `key.js`,
  `rotor-worker.js` with `include_str!`/`include_bytes!`. The coordinator
  cannot build if a site file is missing or renamed.
- **Wasm -> site -> coordinator.** `apps/site/rotor_wasm.wasm` is a committed
  artifact rebuilt by `scripts/build-wasm.sh` from `crates/rotor-wasm`, then
  embedded by the coordinator. The `Dockerfile` rebuilds it during the image
  build. After any `crates/rotor-wasm` change, rebuild, run
  `crates/rotor-wasm/smoke.mjs` and `apps/site/worker-test.mjs`, and commit the
  artifact.
- **Asset revalidation.** Never stamp `?v=` tokens on served files. HTML is
  served with `no-store` and references every first-party asset as
  `/a/<build>/<path>`; those URLs are immutable (the build changes on every
  deploy), while bare asset paths (old links, curl) stay `no-cache` with a
  content `ETag`. `node scripts/check-projects.mjs` rejects a returning token.
- **Vendored pilot assets.** `web/public/**` mirrors `apps/site/**`. Vendored
  identity is content after EOL normalization (CRLF folded to LF), so one
  digest is correct on Windows and Linux. `data/vendor.lock.json` records
  `{source, target, sha256}` for every pair. After an `apps/site` edit or a
  merge, run `node scripts/gen-ssot.mjs --vendor-lock` to refresh the copies and
  digests. `node scripts/check-ssot.mjs` fails on a drifted copy, a stale digest
  or a file under `web/public/` the lock does not cover. Deliberate non-copies
  (the WalletConnect and TON bundles) are listed with a reason.
- **Detector registry.** `data/detectors.json` is the one detector registry
  (`id`, `rule`, `batch`, `implemented_in`, `doc_anchor`, `status`). The three
  human tables are generated by `node scripts/gen-detector-docs.mjs`;
  `check-ssot` fails when an id emitted by `scripts/ui-audit.mjs` or a
  `docs/process/defects.json` detector has no implemented entry, and when the
  generated tables drift.
- **Routes.** `/`, `/app`, `/run`, `/me`, `/docs`, `/key` and the static asset
  routes are a fixed set in `src/coordinator/mod.rs`; changing one is a
  coordinator + site change. Key utility pages `/hex-dec-bin`, `/public-key`,
  `/pubkey-add`, `/reconstruction` and `/keystore-parser` (plus `key-tools.js`
  and their per-page scripts) follow the same rule. The transaction decoders
  are served on `/tx`, `/tx/bitcoin` and `/tx/ethereum`, sharing
  `tx-decoders.js` (pure Bitcoin/EIP-2718 codecs) and `tx-page.js` (DOM
  wiring); they decode raw hex locally, make no network request, and a Bitcoin
  fee is only reported when prevout values are supplied. The cabinet wallet lives on
  `/cabinet/wallet` and shares `wallet-vault.js` (the pure encrypted-vault
  codec), `wallet-evm.js` (the pure Sepolia send flow: validation, chain-id
  guard, review and confirm over an injected RPC), `wallet-btc.js` (the pure
  Bitcoin testnet send flow: bech32 validation, coin selection, dust/change,
  review and confirm over injected UTXO/broadcast callbacks) and `wallet.js`
  (page logic);
  the coordinator never receives a key, WIF or passphrase. The cabinet at
  `/cabinet` shares `monitor.js` and `wc-links.js` (pure WalletConnect
  deep-link builders and mobile detection) and lazy-loads the vendored
  `walletconnect.js` bundle; the provider is built with `showQrModal: false`
  and the page renders its own URI/QR/deep-link panel. `/assets.generated.js`
  carries the `data/assets.json` top-10 list and `/wallet-assets.js` its pure
  ordering/price/row model; the wallet page also loads the shared
  `balance-cache.js` and `balance-providers.js` for native rows. The operator cabinet
  lives at `/cabinet/admin` behind a signed session cookie (login at
  `/cabinet/admin/login`, dashboard data at `/cabinet/admin/api/overview`, both
  scoped to `Path=/cabinet/admin`); its read-only inventory panels
  (`/cabinet/admin/{clients,monitor,jobs,orders,providers,integrations,audit}`)
  read `/cabinet/admin/api/*` with bounded pagination. The design gallery moved
  to `/cabinet/admin/design` and the old `/design` route answers 404. The
  routing map is `/cabinet/admin/site-map`, a matrix of every route family from
  `data/routes.json` with its template, renderer, data sources, auth and status;
  `node scripts/check-ssot.mjs` fails when the coordinator serves a route that
  is missing from the map or when a mapped template file does not exist. The
  cabinet assets are `/admin.js`, `/admin.css` and `/site-map-admin.js`. The seed studio is served
  on `/seed` and `/mnemonic-converter`, sharing `seed.js`, `seed-crypto.js`,
  `seed-page.js` and `seed-studio.css`; the directory remains on
  `/mnemonic-seeds`. Brainwallet pages share `brainwallet-engine.js`
  (138-word corpus, BigInt page math, phrase hash, chain row selection,
  explorer links), `brainwallet-directory.js` (18,890-passphrase directory,
  60 rows per page, 315 pages, optional balances) and `brainwallet.js` (the
  single-passphrase generator on `/brainwallet-generator`). `/brainwallet` is
  the index of 18 chain directories; `/brainwallet/<chain>` and
  `/brainwallet/<chain>/<page>` are the directory pages. SEO routes include
  `/bitcoin-puzzle`, `/bitcoin-puzzle/<n>` (canonical detail; the legacy
  `/bitcoin-puzzle/<n>/detail` permanently redirects to it),
  `/bitcoin-puzzle/<n>/random` and `/bitcoin-puzzle/unsolved` for n in 1..=160.
  The route/feature parity map is internal documentation, not a public route:
  it lives in `docs/site-map/index.html` with `site-map.css`, `site-map.js` and
  the single data file `site-map-data.js`. It covers donor parity only and
  defers route facts to `data/routes.json`; `site-map-test.mjs` requires every
  route it lists to exist in that map. The coordinator embeds neither file.
  `data/routes.json` is the routing SSOT: one entry per route family (pattern,
  template, renderer, data sources, auth, status), gated by `check-ssot`.
- **Desktop -> infra.** `build.rs` compiles the CUDA sources under
  `Rotor-Cuda/`; moving them requires `build.rs`, `Cargo.toml` and
  `gpu-bsgs-compile.yml` in the same change.
- **Docs/specs.** Behavior or contract changes update `openspec/` and declare
  `Areas:` in the change.

## Scripts

```sh
node scripts/check-projects.mjs                  # schema, ownership, coverage
node scripts/affected-areas.mjs                  # diff origin/main + working tree
node scripts/affected-areas.mjs path/to/file ... # explicit paths
node scripts/ui-audit.mjs --serve                # headless UI self-review (site)
node scripts/density-parity.mjs --donor URL --ours URL [--json PATH]  # donor-vs-ours density
node scripts/sync-board.mjs [--dry-run]          # epics, sub-issues, blockers, PR links
node scripts/check-task-links.mjs --pr 123       # PR task key + closing reference gate
node scripts/revert-fix.mjs --base origin/main --projects-area site  # revert the fix, require a red test
```

The full gate inventory (cost, required/advisory) is
[`docs/process/gates.md`](docs/process/gates.md). `scripts/revert-fix.mjs` is
the always-on mutation tier: it reverts non-test executable hunks for affected
areas and requires the area tests to fail.

`scripts/ui-audit.mjs` is the shared UI gate: headless Chrome/Edge over CDP
(zero dependencies), every route at 375/768/1280 in dark and light, with
screenshots and a JSON report. It checks overflow, text below 12px, touch
targets below 44px, icon-only controls without labels, duplicated address-type
components, uneven card widths, half-empty cards, manual balance controls and
the route-specific row counts. Exit 1 means a UI change is not done. The
failure table and workflow live in `.claude/skills/ui-self-review/SKILL.md`.

`scripts/density-parity.mjs` is the donor measurement gate: the same zero-dependency
headless Chrome/Edge CDP path, two URLs, three viewports, and a report of chrome
height (document top to the first data row), visible rows and row height,
interactive controls above the fold, block padding/gaps, title/stat/table-header
font sizes and document height. It never invents donor numbers: an unreachable
donor is reported with the raw reason while our side is still measured. The
procedure lives in `.claude/skills/donor-reverse/SKILL.md`; the first measured
run is `docs/donor-parity/density-tron.md` with its raw JSON beside it.

`scripts/sync-board.mjs` maintains the task-tracking issues: one epic per
OpenSpec change, one sub-issue per `tasks.md` section (title `ROT-<n> — <task>`,
marker `<!-- openspec-task: <change>/<slug> -->`), `Blocked by: ROT-<n>` edges
from the section's `blocked by:` line, native sub-issue links over GraphQL, and
`Closes #<n>` in open PRs that name a key and follow the branch convention. It
mirrors every change and open pull request into the Rotor Project (owner
`mytab0r`, number 3) with `Area`, `Progress` and `Status` fields. It runs
locally with the owner's `gh` login (`repo` and `project` scopes), requires
Issues to be enabled, creates `change:<id>` labels on demand, and never closes
an issue. `--dry-run` prints the plan without a single mutation. The full
convention is `docs/process/task-tracking.md`.

`scripts/check-task-links.mjs` is the `pull_request` gate
(`.github/workflows/task-links.yml`): it fails when the PR body lacks
`Task: ROT-<n>`, when the issue does not exist, or when the closing reference
to that issue is missing. A docs/process-only PR may use
`Task: none — <reason>`.

Reading order: `AGENTS.md` -> this file -> the area `AGENTS.md` -> the
`openspec/` change or spec.
